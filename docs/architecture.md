# Architecture

## Ownership and imports

```text
app → features → shared modules
app ───────────→ shared modules
```

- **`app/`** owns routing, layouts, providers, and composition. Pages may compose multiple independent features.
- **`features/<name>/`** owns its UI, schemas, actions, server operations, types, and colocated tests. Import within the same feature or from shared modules, never from another feature or `app/`.
- **Shared modules** (`components/`, `lib/`, `hooks/`, `i18n/`, and other shared directories covered by lint) do not import `features/` or `app/`. Keep genuinely shared UI in `components/ui/`; do not move business logic there to bypass a boundary.
- Prefer direct file imports; avoid barrels mixing server/client code. Create only needed folders, not a generic CRUD/service framework.

[ESLint](../eslint.config.mjs) enforces the direction of imports. A route composes features and passes feature-owned pieces into shared components as slots. Translation JSON lives in [`messages/`](../messages/), outside features, so every language file has one shape.

## Reference data flow

The contact form is the reference for a form that writes data. Start at [`features/contact/components/contact-form.tsx`](../features/contact/components/contact-form.tsx) and follow its imports.

1. [`schema.ts`](../features/contact/schema.ts) defines the fields once. Validation messages are error codes, not text. `parseContactInput` returns a `Result` and never echoes submitted values.
2. The form uses React Hook Form with the same schema, so most mistakes are caught before a request. It translates error codes with next-intl.
3. [`submitContactAction`](../features/contact/actions.ts) treats its arguments as untrusted and validates them again on the server. It receives the language as an argument, because a Server Action runs outside a route and cannot read the `[locale]` segment.
4. [`submitContactMessage`](../features/contact/server/submit-message.ts) returns a `ResultAsync`. It checks the rate limit, stores the message, and then notifies the owner; a failed notification is logged and does not fail the submission.
5. The action converts the result to a plain union with safe codes. The form branches on it: field errors next to fields, an alert when the server cannot be reached or the visitor is over the limit, and a confirmation on success.

The message is written with `overrideAccess: true` because an anonymous visitor has no CMS account. That is safe only because the collection is closed to the public API and the input was validated one line earlier; say why whenever you bypass access control.

**Rate limit.** A visitor may send five messages in ten minutes ([`CONTACT_RATE_LIMIT`](../features/contact/server/submit-message.ts)). [`lib/rate-limit`](../lib/rate-limit/) stores accepted requests in the `rate-limit-hits` collection, so the limit holds across server instances. The client is identified by its IP address from the request headers, stored only as an HMAC keyed with `PAYLOAD_SECRET`. Any Server Action that writes data or sends e-mail on behalf of an anonymous visitor uses the same module with its own scope and rule.

The form's block shows how a page block uses a feature: [`components/sections/contact-form.tsx`](../components/sections/contact-form.tsx) renders a slot, and the route passes `<ContactForm />` into it, because shared components do not import features.

## Real data boundaries

For a real backend, use the `data-access-setup` skill to plan the contract, security, and cache ownership. After approval, a separate implementation task applies and verifies the plan; the user need not paste generated code.

- Put secrets, privileged clients, and data access in `server-only` modules.
- Validate untrusted input at every server entry point; a form or TypeScript annotation is not a security boundary.
- Recheck authentication and resource authorization inside each real mutation, even if the page already checked access.
- Return minimal safe DTOs, not full database records, credentials, or backend error objects. `NEXT_PUBLIC_*` values are public and embedded at build time.
- Define timeout, retry, freshness, invalidation, and personalized-data isolation deliberately.
- Keep data server-owned by default. For genuinely client-owned server state, reuse the QueryClient in [`app/providers.tsx`](../app/providers.tsx); keep query keys/options/adapters in the owning feature.

## Payload CMS

Payload runs inside the same Next.js app. The site lives in the `app/(frontend)` route group; the admin (`/admin`) and the REST and GraphQL API (`/api`) live in `app/(payload)`. Each group has its own root layout. Files in `app/(payload)` are generated by Payload: regenerate them, do not edit them.

- **Config.** [`payload.config.ts`](../payload.config.ts), with collections in [`payload/collections/`](../payload/collections/). `payload/` is shared code: it does not import `app/` or `features/`.
- **Schema changes.** Change the collection, then run `pnpm payload migrate:create <name>`, `pnpm generate:types`, and `pnpm generate:importmap` if admin components changed. Commit the migration and [`payload-types.ts`](../payload-types.ts) with the change. Development syncs the schema directly; every other environment runs `pnpm payload migrate` and never `push`.
- **Naming.** Postgres truncates identifiers at 63 characters. Give deeply nested fields, blocks, and selects a short `dbName` or `enumName` before the first migration that contains them.
- **Reading content.** Server code uses the Local API (`getPayload({ config })`) from `server-only` modules and returns minimal DTOs. The Local API skips access control by default: for anything done on behalf of a user, pass `user` and `overrideAccess: false`.
- **E-mail.** With `RESEND_API_KEY` and `EMAIL_FROM` set, the CMS sends through Resend; without them every message is written to the server log, so local development needs no key. Templates are React Email components next to the feature that sends them, such as [`features/contact/emails/`](../features/contact/emails/).
- **Accounts and roles.** The `users` collection holds CMS accounts only, with roles `admin` and `editor` ([`payload/access/roles.ts`](../payload/access/roles.ts)). The first account created becomes an admin. Admins invite others: creating an account sends a link to set a password, so passwords are never shared. Without an e-mail adapter the message is written to the server log. Use `isEditor` for content writes, `isAdmin` for accounts and settings, and `publishedOrEditor` for reads on collections with drafts.
- **Pages and blocks.** A page is a list of blocks. Each block has a config in [`payload/blocks/`](../payload/blocks/) with an `interfaceName`, and a component in [`components/sections/`](../components/sections/). [`render-blocks.tsx`](../components/sections/render-blocks.tsx) maps block types to components; a block without a component fails typecheck. To add a block: write the config, add it to `PAGE_BLOCKS`, create the migration and types, write the component, and add it to the renderer. The page with the slug `home` is the home page; other published pages are served at `/<slug>`.
- **Links.** Use [`linkField()`](../payload/fields/link.ts) in configs and [`CmsLink`](../components/cms/cms-link.tsx) to render. It resolves the real address in the visitor's language and renders nothing for a link whose target is gone.
- **Site settings.** The `site-settings` global holds the site name, header and footer navigation, and the default share image. [`getSiteSettings()`](../lib/site-settings/server.ts) loads it for the layout. Admin branding (title suffix, logo, icon) lives in [`payload/admin/branding.tsx`](../payload/admin/branding.tsx); a new project changes that one file.
- **Loading content.** [`features/pages/server/get-page.ts`](../features/pages/server/get-page.ts) is the pattern: a `server-only` module that returns a `ResultAsync` with a small view type, passes the request language, reads through access control, and caches published content by tag.
- **Caching.** Tags come only from [`lib/cache-tags.ts`](../lib/cache-tags.ts). Collections revalidate through [`revalidateCollection`](../payload/hooks/revalidate.ts), which ignores autosaved drafts. Scripts, seeds, and tests pass `context: { disableRevalidate: true }`, because revalidation works only inside a Next.js request.
- **SEO.** Pages get a title, description, share image, and a noindex switch from the SEO plugin ([`payload/plugins/seo.ts`](../payload/plugins/seo.ts)). [`buildMetadata()`](../lib/seo/metadata.ts) turns them into metadata with fallbacks, a canonical address, and an alternate for every language. Only the production deployment is indexed ([`lib/seo/indexing.ts`](../lib/seo/indexing.ts)): everything else sends `X-Robots-Tag: noindex`, a disallow-all `robots.txt`, and an empty sitemap. Off Vercel, set `ALLOW_INDEXING=true` on the production instance.
- **Redirects.** Editors manage redirects in the CMS ([`payload/plugins/redirects.ts`](../payload/plugins/redirects.ts)). Saving refuses loops, chains, duplicates, and a source that is a live page. Renaming a published page creates a permanent redirect from its old address to the page itself. Redirects apply only where the site would answer 404 ([`findRedirect()`](../lib/redirects/server.ts)), so one never hides a page and all of them work without a deploy. Do not put content redirects in `proxy.ts` or `next.config.ts`.
- **Seed.** `ALLOW_SEED=true pnpm seed` fills the CMS with a home page, a contact page, navigation, and one image, in every language ([`scripts/seed.ts`](../scripts/seed.ts)). It runs in one transaction, updates its own content instead of duplicating it, and refuses to run unless `ALLOW_SEED` is exactly `true`. It writes outside the running site and cannot revalidate its cache, so it deletes the local Next.js data cache; restart a running server afterwards. Any script that writes content this way needs the same step.
- **Drafts and preview.** Visitors see published content only. The CMS preview opens [`/api/preview`](../app/api/preview/route.ts), which requires the `PREVIEW_SECRET` and a signed-in editor, checks the target path against open redirects, and turns on draft mode. In draft mode loaders skip the cache and read the latest draft. Without `PREVIEW_SECRET` the preview is off. Add a collection to preview in `previewPath()` in [`lib/cms/preview.ts`](../lib/cms/preview.ts) and in `admin.livePreview` in the config.
- **Scheduled publishing.** A page can be scheduled; a job publishes it. [`vercel.json`](../vercel.json) calls `/api/payload-jobs/run` every five minutes with the `CRON_SECRET` bearer token. The endpoint also accepts a signed-in admin and refuses everyone else. On other hosts, call the same endpoint from any scheduler with the header `Authorization: Bearer <CRON_SECRET>`.
- **Media.** The `media` collection takes images and PDF files, requires alt text for images, and generates WebP sizes (`thumb`, `card`, `hero`) plus a blur placeholder. Render them with [`CmsImage`](../components/ui/cms-image.tsx), which picks a size and passes alt text and real dimensions. Storage is configured in one place, [`payload/plugins/storage.ts`](../payload/plugins/storage.ts): Vercel Blob when `BLOB_READ_WRITE_TOKEN` is set, local disk otherwise, with the same database schema in both cases. To use another provider, replace the adapter there and keep `alwaysInsertFields`.
- **End users.** Site visitors are not CMS users. If a project needs visitor accounts, add a separate auth collection (for example `customers`) with its own access rules and a feature in `features/` that owns the sign-in flow. Do not add visitor roles to `users`: everyone in that collection can open the admin.
- **Locale routing.** [`proxy.ts`](../proxy.ts) excludes `/admin` and `/api` from locale handling. Add any other non-localized route to its matcher.

## Languages

[`i18n/config.ts`](../i18n/config.ts) is the only list of the site's languages. Routing, message loading, and the CMS content locales all read it. The default language has no URL prefix (`/about`); the others do (`/en/about`). A visitor whose browser prefers another configured language is redirected to it on the first visit.

- **Site text** lives in `messages/<locale>.json`. Czech is the reference shape: [`i18n/messages.ts`](../i18n/messages.ts) fails typecheck when a language misses a key.
- **CMS content** is localized per field (`localized: true`), never as one document per language. Every content query passes the request language from [`getContentLocale()`](../lib/cms/locale.ts); without it Payload returns the default language on every page.
- **Add a language:** add it to `LOCALES` and `LOCALE_LABELS`, add `messages/<locale>.json`, register it in `i18n/messages.ts`, then run `pnpm payload migrate:create add-<locale>` and `pnpm generate:types`. Typecheck and `i18n/config.test.ts` point at anything missed.
- **Use one language only:** reduce `LOCALES` to it, delete the other message files and their imports, remove the `LocaleSwitcher`, and create a migration. Keep the `[locale]` segment; it costs nothing and keeps a second language cheap to add later.

## Deployment

[Environments](environments.md) lists what each environment uses and how to set up Vercel or another host. [Migrations](migrations.md) has the rules for schema changes.

- **Build.** `pnpm vercel-build` runs migrations when [`migrationDecision()`](../lib/deploy/migration-policy.ts) allows it, then builds. Production migrates; a preview migrates only with `PREVIEW_DATABASE_ISOLATED=true`, so a preview can never migrate a database it shares with production.
- **Health.** `/api/health` answers 200 when the database responds and 503 when it does not.
- **Headers.** [`securityHeaders()`](../lib/security/headers.ts) applies to every response. There is no Content Security Policy; see [decisions](decisions.md).

## Errors and monitoring

Expected failures are `Result` values, handled where they occur. Everything else is unexpected and ends in one place: [`captureError()`](../lib/observability.ts), which writes a structured log line with secrets and e-mail addresses removed. [`instrumentation.ts`](../instrumentation.ts) sends every unhandled server error there.

- **What visitors see.** [`error.tsx`](../app/(frontend)/[locale]/error.tsx) and [`not-found.tsx`](../app/(frontend)/[locale]/not-found.tsx) are translated and show no technical detail. [`global-error.tsx`](../app/global-error.tsx) covers a failing root layout.
- **Old tabs after a deploy.** A tab opened before a deploy calls Server Actions the new build does not know. Wrap action calls as the contact form does: [`reloadOnStaleDeployment()`](../lib/stale-deployment.ts) reloads the page for that one error.
- **Adding an error tracker.** The template ships none. To add Sentry or another service: install its SDK, initialize it in `register()` in `instrumentation.ts`, and call `setErrorReporter((error, context) => …)` there. Add its variables to `lib/env-schema.ts`. Browser-side tracking needs the SDK's own client setup. Never send what `captureError` scrubs: pass the tracker the same scrubbed context.

## Environment

[`lib/env-schema.ts`](../lib/env-schema.ts) is the only definition of server environment variables. [`lib/env.ts`](../lib/env.ts) validates them once at startup and is the only place server code reads them; a missing or malformed variable stops the build or the server with an error that names the variable, never its value. Add a variable to the schema and to [`.env.example`](../.env.example) in the same change. The schema module stays free of `server-only` so CLI tools outside Next.js can reuse it.

## One error contract

| Layer | Expected failure representation |
| --- | --- |
| Internal domain/data operation | `Result<T, E>` / `ResultAsync<T, E>` with a typed domain error |
| Server Action | Plain serializable discriminated union with safe codes |
| Direct action UI | Branch on the union and translate known codes |
| Optional TanStack Query adapter | Convert failure to rejected Promise so Query enters its error state |
| UI notification | Safe translated message through `toast.add({ type, title })` plus inline recovery where needed |

Only the Query adapter performs the expected-error-to-rejection conversion. Do not throw expected validation errors in the action or return `Result` instances over the React boundary. Unexpected transport errors get a generic message; never render arbitrary server `Error.message`. Keep framework redirects/not-found control flow outside domain error conversion.

[`Toaster`](../components/ui/toast.tsx) is mounted by the shared provider. Reuse the exported manager instead of adding a renderer per feature. The [Query error skill](../.agents/skills/react-query-server-action-errors/SKILL.md) describes an optional adapter; the demo intentionally does not contain a compiled Query mutation.
